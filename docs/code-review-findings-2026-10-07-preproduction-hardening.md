# Code Review Findings: 2026-10-07

> **Discovery stage:** Full implementation review during MVP pre-production hardening, after core feature implementation and before relying on production deployment.
>
> This is a dated snapshot of findings from that review. Record findings from future reviews in a new dated file so each review's scope and status remain traceable.

Findings from the full implementation review, prioritized by impact. This list excludes the accessibility and responsive polish already marked outstanding in the frontend tracker.

## P1: Fix Before Relying on Production

- [x] **Guest job filters leak owner state.** `/api/jobs` ignores owner-only `status` filters and JEV-confidence sorting for guests; the API regression test asserts membership, order, and count are unchanged by those query parameters. See [server.ts](../src/server.ts#L168).
- [x] **PostgreSQL is not selected on cold start.** Server and CLI startup now await repository initialization; production requires a successful PostgreSQL probe and cannot lazily fall back to files. Selector tests cover healthy, missing, unavailable, and forced-file branches. The successful live-PostgreSQL path still needs integration verification. See [index.ts](../src/db/index.ts#L17), [server.ts](../src/server.ts#L1341).
- [x] **Production migrations are missing from the image.** SQL migrations are copied into `dist` by the server build; shared repository initialization applies unapplied migrations transactionally before web/CLI use. An advisory lock and migration ledger prevent concurrent/repeated application, and an empty migration directory fails. Runner tests cover apply-once, rerun, empty-directory, and rollback behavior. Live PostgreSQL execution remains unverified. See [migrator.ts](../src/db/migrations/migrator.ts#L14), [Dockerfile](../Dockerfile#L34).
- [x] **PostgreSQL application creation uses invalid IDs.** The API now generates UUID primary keys and the API regression test asserts UUID format. A live PostgreSQL insert remains unverified until the disposable-PostgreSQL suite is available. See [server.ts](../src/server.ts#L773), [001_initial_schema.sql](../src/db/migrations/001_initial_schema.sql#L95).
- [x] **Owner AI can overwrite the canonical resume without confirmation.** Removed the profile-mutating `ingest_resume` tool from the conversation tool surface; Setup remains the explicit owner-controlled profile/resume mutation path. A regression test asserts the default tool inventory excludes it. See [tools/index.ts](../src/ai/agent/tools/index.ts#L20), [agent.test.ts](../src/ai/agent/__tests__/agent.test.ts#L33), [application-agent.md](../requirements/application-agent.md#L72).
- [x] **Guest 429s can trigger owner paid failover.** Failover now activates only for `owner_free` 429s, retries the current turn once with the configured Pro key, and leaves guest quota errors on the isolated guest key. Regression tests cover guest isolation and same-turn owner retry. See [gemini-agent.ts](../src/ai/agent/gemini-agent.ts#L124), [agent.test.ts](../src/ai/agent/__tests__/agent.test.ts#L34), [auth.md](../requirements/auth.md#L63).

## P2: Correctness and Contract Gaps

- [x] **Resume URL sync permits SSRF.** Sync now accepts only HTTPS standard-port targets that resolve exclusively to public addresses, pins the connection to a validated IP, and manually revalidates up to five redirects. Regression tests cover unsafe schemes/private targets, private redirect rejection, and no profile mutation. See [safe-resume-fetch.ts](../src/utils/safe-resume-fetch.ts), [api-endpoints.test.ts](../src/pipeline/__tests__/api-endpoints.test.ts), [api.md](../requirements/api.md#L33), [architecture.md](../requirements/architecture.md#L77).
- [x] **Advertised PDF resume upload is not parsed.** MVP upload is now explicitly JSON Resume `.json` only in the UI and API; PDF/Markdown/plain text are rejected without changing stored profile data. Non-JSON extraction is deferred to a user-confirmed Setup workflow. See [candidate-profile-editor.tsx](../src/client/components/candidate-profile-editor.tsx#L183), [server.ts](../src/server.ts#L402).
- [x] **API status payloads are not enum-validated.** Job status PATCH and application create/update now validate with the existing Zod enums; invalid values return 400 without creating or mutating records or stage history. API regression tests cover all three write paths. See [server.ts](../src/server.ts#L228), [job-posting.ts](../src/types/job-posting.ts#L10), [api-endpoints.test.ts](../src/pipeline/__tests__/api-endpoints.test.ts).
- [x] **Dashboard metrics are inaccurate in PostgreSQL mode.** A shared metrics aggregator excludes `preparing` from submitted-application counts and rates, maps applications to posting sources, and returns the complete source contract in both repositories. A fake-PostgreSQL parity test verifies the file and PostgreSQL results match. See [metrics.ts](../src/db/metrics.ts), [applications-and-metrics.test.ts](../src/pipeline/__tests__/applications-and-metrics.test.ts), [api.md](../requirements/api.md#L22).
- [x] **Saved search filters do not all affect filtering.** Known workplace types now honor `allowedTypes`; onsite distance uses offline ZIP/city-state centroids and the saved radius plus buffer. Unresolvable locations remain unknown and pass, replacing the hard-coded city blacklist. Radius and buffer are editable numeric controls. Regression tests cover disallowed type, nearby onsite, and unknown location. See [deterministic-filter.ts](../src/pipeline/deterministic-filter.ts#L110), [search-profile-editor.tsx](../src/client/components/search-profile-editor.tsx#L424), [crawler.md](../requirements/crawler.md#L141).
- [x] **Discovery reports false success and recommendation counts.** Per-source results now distinguish success/failure; partial runs return HTTP 207 with source errors, all-failure runs return HTTP 502, and recommendations count only positive JEV fits. The API suite covers complete, partial, failed, and positive/negative fit cases. See [server.ts](../src/server.ts#L650), [api-endpoints.test.ts](../src/pipeline/__tests__/api-endpoints.test.ts), [discovery-runs-panel.tsx](../src/client/components/discovery-runs-panel.tsx).
- [x] **Kanban omits valid application stages.** Kanban and drawer now share all ten schema statuses; active and archived buckets are disjoint, with accepted/rejected/withdrawn/inactive archived and offer active. Tests assert full stage coverage and segment membership. See [application-stages.ts](../src/client/components/application-stages.ts), [applications-page.test.ts](../src/client/pages/__tests__/applications-page.test.ts), [page-applications.md](../requirements/frontend/page-applications.md#L7).
- [x] **System health reports inaccurate status.** The panel now maps real PostgreSQL connectivity to Connected/Unavailable/Unknown, distinguishes file mode, and renders exact Gemini tier/failover states. Helper and API contract tests cover connection states and `owner_pro` labels. See [system-health-panel.tsx](../src/client/components/system-health-panel.tsx), [system-health-status.ts](../src/client/components/system-health-status.ts), [setup-page.test.ts](../src/client/pages/__tests__/setup-page.test.ts).
- [x] **Job status route is registered twice.** Consolidated to one validated handler with a server-controlled audit actor (`user` for interactive owners, `system` for bearer automation); caller-supplied `changedBy` is ignored. API tests cover both identities and spoofed body values. See [server.ts](../src/server.ts#L232), [api-endpoints.test.ts](../src/pipeline/__tests__/api-endpoints.test.ts), [api.md](../requirements/api.md#L55).
